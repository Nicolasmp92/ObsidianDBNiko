# 🅰️ 2. Instalación del Entorno — Node.js y Angular CLI

Angular no se instala solo: es un **CLI de npm**, así que primero va Node.js.

## 1. Instalar Node.js (LTS)

Angular requiere una versión LTS activa de Node. Recomendado instalarlo con **nvm** para poder cambiar de versión por proyecto:

```bash
# nvm (Linux/WSL2)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# cerrar y reabrir la terminal, luego:
nvm install --lts
nvm use --lts
```

Alternativa directa en Ubuntu/Debian (sin nvm): paquetes de NodeSource o `sudo apt install nodejs npm` — ojo, el de `apt` suele venir viejo.

## 2. Verificar

```bash
node --version   # v22.x o superior (LTS)
npm --version    # 10.x o superior
```

## 3. Instalar Angular CLI

```bash
npm install -g @angular/cli
ng version
```

`ng version` debe mostrar Angular CLI 22.x junto a tu versión de Node.

> [!TIP] Solo npm
> Todo el flujo Angular de este vault usa **npm** exclusivamente (nada de yarn/pnpm/bun) — es lo que fijan los [[Estándares Front-End - Angular|estándares front]].

## 4. Herramientas que acompañan

| Herramienta | Para qué | Instalación |
|---|---|---|
| Angular DevTools | Inspeccionar componentes/signals en Chrome/Edge | Extensión del navegador |
| VS Code + Angular Language Service | Autocompletado y errores en templates | `angular.ng-template` |

## ⚠️ Errores típicos

| Error | Causa | Fix |
|---|---|---|
| `ng: command not found` | npm global no está en el PATH, o acabas de instalar nvm | Reabrir terminal; `npm config get prefix` debe estar en el PATH |
| `EBADENGINE` al `ng new` | Node viejo para el CLI nuevo | `nvm use --lts` |
| Permisos `EACCES` en `-g` | npm global mal configurado | Configurar prefix de npm en `~/.npm-global` — **nunca `sudo npm -g`** |
