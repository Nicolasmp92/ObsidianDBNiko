# 💾🌐 Volúmenes y Redes en Docker

Los contenedores son **efímeros**: si lo borras, todo lo de dentro desaparece. Para que los datos sobrevivan y los servicios se comuniquen existen los volúmenes y las redes.

## 💾 Volúmenes (persistencia)

| Tipo | Sintaxis | Cuándo usarlo |
|---|---|---|
| **Named volume** | `-v dbdata:/var/lib/mysql` | Datos que Docker gestiona: bases de datos, uploads |
| **Bind mount** | `-v ./:/var/www/html` | Tu código en desarrollo: editas en tu PC y el contenedor lo ve al instante |
| **tmpfs** | `--tmpfs /tmp` | Datos temporales en RAM |

```bash
docker volume ls                 # listar volúmenes
docker volume create dbdata      # crear uno
docker volume rm dbdata          # borrar (¡pierdes los datos!)
```

> [!WARNING] El error clásico
> Levantar MySQL sin volumen y preguntarse por qué "se borraron los datos" al hacer `down`. La BD siempre va en un **named volume**.

## 🌐 Redes (cómo se hablan los contenedores)

- Docker crea una red `bridge` por defecto.
- **Docker Compose** crea una red propia por proyecto: los servicios se resuelven por **nombre de servicio** (`db`, `app`, `redis`).

```bash
docker network ls                        # ver redes
docker network create mi_red             # crear una
docker run --network mi_red ...          # conectar contenedor
```

- Dos contenedores en la misma red se ven entre sí; en redes distintas están aislados.
- Publicar con `-p` expone el puerto al exterior; dentro de la red no hace falta publicar nada.

> [!TIP] Regla práctica
> Comunicación interna → por nombre de servicio dentro de la red de Compose. Acceso externo → solo el servicio "frontal" (nginx) publica puertos.
