# 🎼 Docker Compose: Orquestar Contenedores

Un proyecto real no es un contenedor: es **app + base de datos + servidor web**. En lugar de tres `docker run` imposibles de recordar, declaras todo en un `docker-compose.yml` y lo levantas con un solo comando.

## Ejemplo: stack Laravel (PHP-FPM + Nginx + MySQL)

```yaml
services:
  app:
    build: .                      # usa tu Dockerfile
    volumes:
      - ./:/var/www/html          # tu código sincronizado (bind mount)
    depends_on:
      - db

  nginx:
    image: nginx:alpine
    ports:
      - "8080:80"                 # localhost:8080 → app
    volumes:
      - ./:/var/www/html
      - ./nginx.conf:/etc/nginx/conf.d/default.conf
    depends_on:
      - app

  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: secret
      MYSQL_DATABASE: mi_app
    volumes:
      - dbdata:/var/lib/mysql     # datos persistentes (named volume)

volumes:
  dbdata:
```

## Comandos del día a día

| Acción | Comando |
|---|---|
| Levantar todo (background) | `docker compose up -d` |
| Ver estado de los servicios | `docker compose ps` |
| Logs en vivo | `docker compose logs -f` |
| Entrar a un servicio | `docker compose exec app bash` |
| Reconstruir tras cambiar el Dockerfile | `docker compose up -d --build` |
| Apagar todo | `docker compose down` |
| Apagar + borrar volúmenes (¡BD!) | `docker compose down -v` |

> [!TIP] La magia de Compose
> Compose crea una **red interna** automática: los servicios se encuentran por nombre. Desde `app` conectas a MySQL con `DB_HOST=db` — no necesitas IPs.
