# 🔨 Dockerfile: Construir Imágenes Propias

Cuando las imágenes de Docker Hub no bastan (necesitas extensiones de PHP, Node, configs propias), escribes tu propia receta: el **Dockerfile**.

## Instrucciones base

| Instrucción | Qué hace |
|---|---|
| `FROM` | Imagen base de la que partes (`php:8.3-fpm`) |
| `WORKDIR` | Carpeta de trabajo dentro del contenedor |
| `COPY` / `ADD` | Copia archivos de tu PC al contenedor |
| `RUN` | Ejecuta comandos al **construir** la imagen (instalar paquetes) |
| `EXPOSE` | Documenta el puerto que usa la app |
| `CMD` / `ENTRYPOINT` | Comando que corre al **iniciar** el contenedor |

## Ejemplo: imagen PHP para Laravel

```dockerfile
FROM php:8.3-fpm

WORKDIR /var/www/html

# Dependencias del sistema + extensiones PHP típicas de Laravel
RUN apt-get update && apt-get install -y \
    git unzip libpng-dev libonig-dev libxml2-dev \
    && docker-php-ext-install pdo_mysql mbstring exif pcntl bcmath gd

# Composer dentro de la imagen
COPY --from=composer:latest /usr/bin/composer /usr/bin/composer

COPY . .

CMD ["php-fpm"]
```

## Construir y usar

```bash
docker build -t mi-app:1.0 .      # construir (el punto = contexto actual)
docker run -d --name app mi-app:1.0
```

> [!TIP] Caché de capas
> Cada instrucción genera una capa cacheada. Ordena el Dockerfile de **lo que menos cambia a lo que más cambia**: primero `apt-get`/extensiones, al final `COPY . .` — así los rebuilds son rápidos.

> [!NOTE] `.dockerignore`
> Como el `.gitignore` pero para el contexto de build: excluye `node_modules`, `vendor`, `.git` para imágenes más livianas.
