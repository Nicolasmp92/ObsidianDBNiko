## 💻 Instalación y Configuración del Entorno (WSL2)

El error más común es trabajar desde la terminal de Windows (PowerShell) con archivos en `C:\`. Esto hace que Docker sea extremadamente lento. La forma correcta es **dentro de la distribución de Linux**.

### 0. Instalar Docker

- **En Windows:** instala **Docker Desktop** desde docker.com — trae la integración con WSL2 incluida.
- **En Linux nativo (Ubuntu/Debian):**

```bash
sudo apt update && sudo apt install docker.io docker-compose-v2
```

- **Verificación:** `docker --version` y luego `docker run hello-world` — si ves el mensaje de bienvenida, el motor funciona.

### 1. Preparar la Distro Linux

Si no tienes una, lo más recomendable es instalar Ubuntu desde la Microsoft Store o vía terminal:

```powershell
wsl --install -d Ubuntu
```

En Docker Desktop, activa la integración: _Settings → Resources → WSL Integration → Ubuntu_.

### 2. Integración con VS Code

Para que la experiencia sea fluida, es obligatorio instalar la extensión **"WSL"** de Microsoft en Visual Studio Code.

- **Flujo de trabajo:** Abre tu terminal de Ubuntu, navega a tu carpeta de proyectos y escribe `code .`.
    
- **Resultado:** VS Code se conectará al interior de Linux. Docker detectará esto y la velocidad de lectura/escritura de archivos será nativa (hasta 10 veces más rápida que desde Windows directamente).
    

### 3. Permisos y Usuarios (Pro-tip para la Wiki)

En entornos Linux, Docker suele requerir `sudo`. Para evitar esto dentro de tu WSL2, añade tu usuario al grupo docker:

```bash
sudo usermod -aG docker $USER
```

_(Es necesario cerrar y abrir la terminal para que los cambios surtan efecto)._

> [!TIP] Verificación final
> Corre `docker run hello-world` **sin sudo** dentro de Ubuntu. Si funciona, el entorno quedó perfecto.
