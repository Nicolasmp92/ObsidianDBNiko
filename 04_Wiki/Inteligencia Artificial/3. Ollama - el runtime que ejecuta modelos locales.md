# Ollama — el runtime que ejecuta modelos locales

> **Pregunta que responde esta nota:** si un modelo de IA es "solo un archivo gigante", ¿qué programa lo hace funcionar en mi PC?
>
> **Respuesta corta:** un **runtime de inferencia**. Ollama es el más popular: descarga modelos con un comando, los ejecuta en tu GPU/CPU y te da una API local en `localhost:11434` igual a la de OpenAI.

## 1. Primero lo primero: qué es un "modelo"

Un LLM (Large Language Model) como ChatGPT, Llama o Qwen es, en esencia, **un archivo enorme de números** — los "pesos" aprendidos durante su entrenamiento. Un modelo de 7 mil millones de parámetros es literalmente un archivo con 7.000.000.000 de números.

- **Entrenamiento** = ajustar esos números leyendo medio internet (semanas, cientos de GPUs, millones de dólares). Eso ya lo hizo alguien por ti.
- **Inferencia** = *usar* el archivo para generar texto: le das palabras, el modelo predice el siguiente pedazo de palabra (token), repite millones de veces por segundo. Esto es lo que haremos localmente — infinitamente más barato.

## 2. Por qué necesitas un runtime

El archivo de pesos no se "ejecuta" solo. Necesitas un programa que:

1. **Cargue** los pesos en memoria (VRAM de la GPU o RAM).
2. **Ejecute la matemática** de la red neuronal — millones de multiplicaciones por token, idealmente en GPU vía CUDA.
3. **Administre el contexto** (la conversación acumulada, el "KV cache").
4. **Tokenice**: convierta tu texto a números y las respuestas de vuelta a texto.

Ese programa es el **runtime de inferencia**. Ollama es uno — y hoy el más usado para uso personal.

## 3. Qué hace Ollama exactamente

Ollama es "baterías incluidas": envuelve al motor **llama.cpp** en una experiencia cómoda:

| Pieza | Qué es |
|---|---|
| `ollama serve` | Servidor local que mantiene el modelo cargado en memoria |
| `ollama pull <modelo>` | Descarga modelos del registry público (como `docker pull`) |
| `ollama run <modelo>` | Chatea directo desde la terminal |
| API REST en `:11434` | Endpoints `/api/generate`, `/api/chat` y compatibilidad con el formato de OpenAI → cualquier app que hable con OpenAI puede hablar con tu modelo local cambiando la URL |
| Gestión de GPU | Detecta CUDA solo y reparte capas entre GPU y CPU si el modelo no cabe entero en VRAM |

Los modelos se descargan en formato **GGUF cuantizado** a `~/.ollama/models`.

## 4. Cuantización — por qué cabe en tu PC

Los pesos originales son números de 16 bits. La **cuantización** los comprime a 8, 5 o 4 bits (Q8, Q5, Q4) con pérdida pequeña de calidad:

- Un 7B en FP16: ~14 GB → no cabe en tu RTX 2060.
- El mismo 7B en **Q4**: ~4-4,5 GB → cabe entero en tus 6 GB de VRAM. ✅

GGUF es el formato de archivo que llama.cpp popularizó para modelos cuantizados. Cuando veas `Q4_K_M` en un nombre de modelo: 4 bits, variante "K", calidad media — el punto dulce habitual.

## 5. Ollama vs las alternativas

| Herramienta | Qué es | Para quién |
|---|---|---|
| **Ollama** | Runtime + gestor + API, todo en uno | Punto de partida estándar — es la elección de myk |
| **llama.cpp** | El motor en C++ que Ollama usa por debajo | Máximo control: compilar, flags finos, formatos raros |
| **LM Studio** | Lo mismo con interfaz gráfica | Quien prefiera ventanas sobre terminal |
| **vLLM** | Runtime de alto rendimiento para servir a muchos usuarios | Producción/servidores, no laptop |

Decisión práctica: Ollama para aprender y usar; si algún día necesitas exprimir rendimiento, ahí está llama.cpp debajo.

## 6. Qué se gana y qué se pierde yendo local

| ✅ Ganas | ❌ Pierdes |
|---|---|
| Privacidad total: nada sale del PC | Modelos top de nube (GPT-5, Claude) son mucho más capaces |
| Costo $0 por token | Tu 6 GB VRAM = límite ~8B parámetros en GPU |
| Funciona offline | Velocidad menor que datacenter |
| Aprendes cómo funciona de verdad | Contexto más chico, sin navegación ni herramientas listas |

## 7. Cómo se usa (lo instalado en este equipo — ver [[MOC - Myk]])

Instalación **portable** en `~/tools/ollama` (sin sudo; el script oficial instala un servicio systemd que requiere root — lo portable permite experimentar sin tocar el sistema):

```bash
~/tools/ollama/bin/ollama serve &          # levanta el servidor en :11434
~/tools/ollama/bin/ollama pull llama3.2:3b # descarga un modelo
~/tools/ollama/bin/ollama run llama3.2:3b  # chatea en la terminal
~/tools/ollama/bin/ollama ps               # ver qué modelo está en VRAM/RAM
```

Y desde código, la API: `curl http://localhost:11434/api/generate -d '{"model":"llama3.2:3b","prompt":"hola","stream":false}'`

> ⚠️ Recuerdo de la nota de Asimov: las "reglas" del modelo irán en el system prompt — texto que **inclina** su conducta, no la garantiza. La seguridad real va por fuera (permisos, sandbox), no dentro del modelo.

## Glosario mínimo

- **Token:** pedazo de palabra (~¾ de palabra en español) — la unidad que el modelo lee y genera.
- **Parámetros:** los números del archivo; más parámetros = más capacidad y más VRAM.
- **VRAM:** memoria de la GPU; lo que cabe ahí corre rápido.
- **Contexto:** cuánto texto "recuerda" el modelo en la conversación (la ventana).
- **Modelfile:** receta de Ollama para personalizar un modelo (system prompt, temperatura, etc.).
