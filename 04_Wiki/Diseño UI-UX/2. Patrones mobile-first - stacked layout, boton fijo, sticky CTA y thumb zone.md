# Patrones mobile-first — stacked layout, botón fijo, sticky CTA y thumb zone

> **Pregunta que responde esta nota:** ¿qué significan estos 4 términos que circulan en el diseño móvil y de conversión, y cómo se implementan en la práctica?
>
> **Respuesta corta:** son el vocabulario básico del **diseño mobile-first orientado a la acción**. Forman un solo patrón cuando se combinan: el contenido se *apila* en una columna (stacked layout), la acción principal queda *fija* en pantalla (botón fixed → sticky CTA) y se ubica donde el pulgar llega sin esfuerzo (thumb zone). El detalle — y los matices que casi nadie cuenta — abajo.

## 1. El mapa: cómo se conectan los 4

```
┌─────────────────┐
│  contenido      │   stacked layout: una columna,
│  apilado        │   se recorre con scroll del pulgar
│  (scroll ↓)     │
│                 │
│  ─ ─ ─ ─ ─ ─ ─  │ ← zona difícil de alcanzar (top)
│                 │
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │   sticky CTA: barra fija abajo,
│ ▓ COMPRAR ▓▓▓▓▓ │   dentro del arco natural del pulgar
└─────────────────┘
```

La lógica es una cadena: si el usuario lee haciendo scroll vertical con el pulgar (así se usa el teléfono), entonces (a) el contenido debe apilarse, (b) la acción importante no puede quedar enterrada al final del scroll → se fija, y (c) se fija *abajo*, no arriba, porque ahí está el pulgar.

## 2. Stacked layout (layout apilado)

**Qué es:** organizar el contenido en una sola columna vertical. En desktop los elementos conviven lado a lado (grillas de 2-4 columnas); en móvil esas mismas columnas *colapsan* apilándose una sobre otra. Es el comportamiento por defecto del diseño responsive bien hecho.

**Por qué importa:**
- El scroll vertical es el gesto más barato en móvil (un swipe del pulgar). En cambio, el scroll horizontal y el ancho forzado rompen la experiencia — ya lo vivimos con el desborde de grillas a 360px en KPP.
- Apilar **cambia el orden de lectura**: lo que en desktop era "izquierda → derecha" pasa a ser "arriba → abajo". El orden en el DOM define qué ve primero el usuario móvil — por eso en mobile-first el CTA y el titular van antes que la imagen decorativa.

**Cómo se implementa:**

```css
/* Grid: columnas en desktop, apilado en móvil */
.cards { display: grid; grid-template-columns: 1fr; gap: 1rem; }
@media (min-width: 768px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}
```

En mobile-first se escribe primero el caso móvil (`1fr` = una columna) y se *escala* a desktop con `min-width`. Lección aprendida en este vault: en grillas usar `minmax(0, 1fr)`, no `1fr` a secas, para que el contenido no desborde la celda (commit `b306d06` de KPP).

## 3. Botón fijo (`position: fixed`)

**Qué es:** un elemento sacado del flujo del documento y anclado al **viewport**: no importa cuánto se haga scroll, sus coordenadas en pantalla no se mueven.

```css
.cta-fijo {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
}
```

**Las dos trampas clásicas:**

1. **Tapa contenido.** Al salir del flujo, el documento "no sabe" que existe: el último párrafo o botón de la página puede quedar permanentemente escondido detrás de la barra. Fix: reservar el espacio.

   ```css
   body { padding-bottom: calc(64px + env(safe-area-inset-bottom)); }
   /* y para que el foco por teclado nunca quede oculto (WCAG 2.2): */
   :focus { scroll-margin-bottom: 80px; }
   ```

2. **El safe-area del teléfono.** En dispositivos con indicador de gestos (iPhone sin botón home), un botón pegado a `bottom: 0` cae dentro de la zona de gesto del sistema. Fix: `padding-bottom: max(16px, env(safe-area-inset-bottom))`.

**`fixed` vs `sticky` — no son lo mismo:**

| | `position: fixed` | `position: sticky` |
|---|---|---|
| Flujo | Sale del documento (no reserva espacio) | Ocupa su lugar normal en el flujo |
| Ancla | Al viewport, siempre | Al ancestro scrolleable, desde un umbral (`top`, `bottom`) |
| Comportamiento | Quieto desde el primer render | Scrollea normal hasta llegar al umbral; ahí se "pega"; se va cuando su contenedor padre sale de pantalla |
| Uso típico | CTA persistente, navbar global, FAB | Encabezados de sección/tablas, barras que se pegan al llegar |

Trampa de `sticky`: solo funciona dentro de su **contenedor padre** — si el padre termina, el elemento se va con él. Y si algún ancestro tiene `overflow: hidden/scroll/auto`, el ancestro scrolleable cambia y puede "romper" el pegado.

## 4. Sticky CTA (llamado a la acción persistente)

**Qué es:** la aplicación comercial de los anteriores — una barra o botón (casi siempre abajo en móvil) con la acción principal ("Comprar", "Reservar", "Añadir al carrito") que sigue visible mientras el usuario lee. En la web se implementa con `fixed` (o `sticky` si el contenedor lo permite).

**Qué dice la evidencia** — no es magia automática:

- GoodUI registró 33 experimentos con sticky CTA: **9 ganadores, 6 perdedores, 18 inconclusos**. Ayuda cuando la página es larga y la decisión requiere leer; estorba cuando se impone antes de tiempo.
- La regla de aparición más repetida: **mostrarlo cuando el CTA del hero sale de pantalla** (IntersectionObserver), no desde la carga — al inicio compite con el propio hero.
- Una sola cosa fija abajo a la vez: si hay banner de cookies, chat o toast, compiten por la misma esquina y el usuario aprende a ignorar toda la zona.
- El copy debe **repetir la promesa del hero**, no inventar una nueva.
- Casos donde sí se muestra siempre: carrito/checkout (el usuario ya se comprometió) — "Checkout (2 ítems) · $48.000".

**Checklist de implementación (consolidado de las fuentes):**

- [ ] Aparece tras un umbral de scroll o cuando el CTA en-flujo desaparece — nunca en la carga (salvo checkout)
- [ ] Solo en móvil (`<768px`); en desktop sobra
- [ ] ~64px de alto + `env(safe-area-inset-bottom)`; botón ≥44-48px (touch target)
- [ ] `padding-bottom` al body igual a la altura de la barra + `scroll-margin-bottom` para el foco
- [ ] Se oculta si un formulario que cumple la misma acción está en pantalla, o mientras el teclado está abierto (`visualViewport`)
- [ ] Entra con `translateY(100%) → 0` en ~200ms; con `prefers-reduced-motion` aparece sin animación
- [ ] Una acción, un label claro y verbal ("Agendar hora"), jerarquía primario/secundario si hay dos

## 5. Thumb zone (zona del pulgar)

**Qué es:** el área de la pantalla que el pulgar alcanza sin esfuerzo sosteniendo el teléfono a una mano. El gráfico clásico la divide en tres: zona natural (verde, abajo-lado contrario al pulgar), zona de estiramiento (amarilla) y zona difícil (roja, esquinas superiores).

**De dónde sale:** la investigación de **Steven Hoober** — 1.333 observaciones de gente usando el teléfono en la calle, aeropuertos y cafés (2013). Cifras duras:

- Agarres: **49% una mano · 36% cuna** (una mano sostiene, la otra toca) **· 15% dos manos**
- Los pulgares ejecutan **~75% de todas las interacciones** con el teléfono
- Consecuencia de diseño: lo importante va en el tercio inferior, no en la esquina superior (de ahí que la navegación móvil migró de arriba a las barras inferiores)

**El matiz que casi nadie cuenta:** el propio Hoober dice hoy que **el gráfico verde/amarillo/rojo es una simplificación incorrecta**. La investigación posterior muestra que la gente **cambia de agarre constantemente** según el contexto (camina, escribe, sostiene un café), usa el dedo índice de la otra mano, y **prefiere tocar el centro de la pantalla**, no el borde. La lección real no es "pon todo abajo a la izquierda" sino:

- Nada crítico que exija alcanzar las esquinas superiores a una mano
- El contenido interactivo principal en el centro-inferior, que sirve a *todos* los agarres
- No asumir una sola postura: el diseño debe funcionar cambiando de mano y de grip

## 6. Lección para nuestros proyectos

- **KPP (POS móvil):** el POS ya vive esto — botón "Nueva venta" full-width es stacked layout + touch target. Candidato natural: sticky CTA de "Cobrar / total" en el flujo de venta cuando la lista de ítems crece.
- **namp.cl / precios:** landing larga + decisión de contacto → sticky CTA móvil "Cotizar" que aparezca cuando el hero sale de vista es el patrón exacto; cuidado con competir con el banner de cookies/chat.
- **Regla general adquirida:** cualquier `fixed` exige su par — espacio reservado (`padding`) + safe-area + orden de capas frente a otros flotantes.

## Glosario mínimo

- **CTA (call to action):** el elemento que invita a la acción principal de la página (botón, enlace, barra).
- **Viewport:** la porción visible de la pantalla; lo que `fixed` usa como referencia.
- **FAB (floating action button):** botón circular flotante de Material Design; un caso particular de elemento fijo.
- **Safe-area:** zona de pantalla libre de obstáculos del sistema (notch, indicador de gestos); se consulta con `env(safe-area-inset-*)`.
- **IntersectionObserver:** API del navegador que avisa cuando un elemento entra/sale del viewport — la forma estándar de gatillar el sticky CTA.
- **Touch target:** tamaño mínimo toqueable; guías: ≥44×44pt (Apple), ≥48×48dp (Material), ≥24×24px CSS (WCAG 2.2 mínimo).
